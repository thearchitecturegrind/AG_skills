# Submittal Filing and Log

You keep the submittal folders and the log in step. Every move gets a log update, and every log update matches a folder.

## Setup

Find two files in the project folder:

1. **Submittal Folder Structure Guide**: the user's stage folders, who moves a submittal between them, naming convention, spec division folder names, and where the folders live.
2. **Submittal log (Excel)**: read its sheet and column headings first. Fill only the columns it has. Never add, rename or reorder columns.

If either is missing, ask for it. Don't guess a folder structure or log layout.

## Stage flow (default; the guide overrides it)

Received -> first reviewer -> consultants (one subfolder each) -> second reviewer -> ready for return -> returned -> filed in the spec division folder.

With two reviewers, the second reviewer's work goes to Ready for Return for the first reviewer's final check.

## What to do

**New submittal arrives.** Read the submittal and identify the number, revision, spec section, title and contractor. Rename it per the guide. Add a row to the log with the stage set to Received, and tell the user which folder it goes in.

**Stage change.** When the user says it moved (sent to consultants, back from a consultant, reviewed), update the log: stage, ball in court (architect or which consultant), dates and comments. Say which folder the file goes to next.

**Consultant comments back.** Log the consultant, the date and their comments. Note which consultants are still outstanding.

**Review comments.** If the submittal-reviewer skill produced comments, put them in the log's comment column as the user's log expects, with the recommended action.

**Returned.** Log the action stamp and return date. Then name the spec division folder from the first two digits of the spec section (05 12 00 goes to the 05 folder), using the guide's folder names. Move the final file there.

**Revise and Resubmit.** The returned file stays filed under its revision. The resubmittal starts at Received with the next revision number (.1, .2) and a new log row linked to the original.

## Moving files

Use whatever access exists: a connected folder on the user's computer, or a connected Drive or SharePoint. If you can't move files in this session, give exact instructions instead: source folder, destination folder, new file name. Never say a file was moved unless a tool confirmed it.

## Safety

- Never delete a file or a log row. Move or mark it.
- Ask before overwriting an existing file or changing an earlier log entry.
- Work on a copy of the log if the user hasn't said it's safe to edit the original.
- After each update, show the changed log row so the user can check it.
