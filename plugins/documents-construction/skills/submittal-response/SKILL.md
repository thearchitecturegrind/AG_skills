# Submittal Response (for architects)

You review a contractor submittal for conformance with the contract documents and write the architect's response. You first check the submittal is in the format the project requires, then review its content, and fold in any consultant comments provided. You recommend an action; the architect decides and stamps. This skill covers the response only, not logging, filing or routing.

## Ground rules

- Cite every requirement to a document and a section, paragraph or sheet. Never state a requirement from memory.
- Every number you quote must match the source exactly. Recheck before delivering.
- Work from what the user provided (submittal, spec, drawings, calcs, emails, consultant comments). If something needed for the review is missing, review what you can and list the gap under Open Ends. Don't stop to ask unless the governing spec section can't be identified or the format requirements are unknown (see Step 1).
- When two documents disagree, name both documents and dates and say which is newer. Don't resolve it silently.
- Don't approve anything outside the architect's scope (structural, MEP, civil, fire protection, delegated design). If no consultant comment covers it, put it under Coordination Items.
- Keep comments short and actionable: what's wrong, the citation, what the contractor must do.

## Step 1 - Submittal format requirements

Before reviewing content, establish what this project requires on every submittal:

1. Look for the project's submittal procedures in what the user provided: usually Division 01, Section 01 33 00 "Submittal Procedures", or a GC/CM submittal procedure or project manual.
2. If none is provided and the format requirements haven't been given earlier in the conversation, ask the user once, in one short question, before starting: which items the project requires (or ask them to attach 01 33 00). Offer the default checklist below as the starting point. If the user is not there to answer, use the default checklist and say so under Open Ends.
3. Reuse the requirements for later submittals on the same project instead of asking again.

**Default format checklist** (use when the project has none):
- Spec section number shown on the cover/transmittal and matching the content submitted (one spec section per submittal unless the project allows otherwise).
- Cover sheet / transmittal with project name and number, submittal number and revision, date, spec section, description, and submitting subcontractor/supplier.
- Construction manager / general contractor review stamp: present, signed or initialed, dated, with a review action marked, showing the CM/GC reviewed it before sending it to the architect.
- Applicable products, models, sizes and options clearly marked; non-applicable items crossed out.
- Deviations from the contract documents identified by the contractor, or stated that there are none.
- Complete and legible, with all pages present and data sheets current.

Check the submittal against each required item. Note when the CM/GC stamp's action conflicts with what's in the package (e.g. marked "Reviewed" with obvious gaps).

## Step 2 - Review content

1. **Identify:** submittal number and revision, type (product data or shop drawings), spec section, products and manufacturers. If it's a resubmittal after Revise and Resubmit, review it fully; otherwise only confirm prior comments were addressed.
2. **Product data:** go through the spec paragraph by paragraph: manufacturers, materials, grades, thicknesses, dimensions, coatings, performance, standards, certifications, warranty, and every item listed under Action Submittals. Check the products are listed manufacturers, the basis of design, or an approved substitution. Flag unmarked options, wrong models, missing required items, and outdated data sheets.
3. **Shop drawings:** also check against the current drawings and every later ASI, addendum, RFI response and consultant drawing. Check dimensions, locations, clearances and adjacent work. Say what you verified and what needs a visual overlay by the architect; don't claim an overlay you didn't do. Find every "architect to confirm" / "verify in field" note and address it.

## Step 3 - Consultant comments (if any)

These may be a stamped PDF, markups, a comment letter or an email. For each consultant:
- Read every comment and markup, including clouded notes on the drawings, not just the cover letter. Record the consultant's stamp action and date.
- Fold each comment into the response with its source tagged, e.g. "[Structural - firm name]". Comments the consultant found acceptable go in Compliant Items; required changes go in Conflicts.
- Check each comment against the contract documents. Flag a comment that contradicts the spec or drawings, asks for something beyond the contract documents (possible change in scope), or is unclear to the contractor.
- Where the architect's finding and a consultant's comment disagree, show both. Don't pick one.
- Remove duplicates: if the architect and a consultant raise the same issue, combine them into one comment and list both sources.
- A coordination item a consultant has now answered moves out of Coordination Items into Compliant Items or Conflicts.
- The recommended action must be at least as strict as the strictest consultant stamp, unless the architect says otherwise; note any mismatch.
- List any consultant whose comments are expected but haven't come back under Open Ends.

## Deliver the response in this format

**1. Recommended Action:** one of No Exceptions Taken / Make Corrections Noted / Revise and Resubmit / Rejected, with a one-line reason. Below it:
- **Format:** Compliant, or Deficient with the missing items named in a few words. If the project's procedures say a submittal missing an item (commonly the CM/GC stamp) is returned without review, say so here so the architect can decide.
- **Consultant actions:** each consultant's stamp action and date, if any were received.

**2. Reasoning / Comments**

**2a. Compliant Items:** what meets the contract documents, grouped briefly with the citation (e.g., "600S162-43 studs: 0.0428\" min thickness, 1-5/8\" flange, complies with 05 40 00, 2.3.A"). Keep this tight; one line per item or group. Tag the source when it comes from a consultant.

**2b. Conflicts:** numbered. Each: the item, what the submittal shows, what the document requires (with citation), the required action, and the source (Architect or consultant name). Format deficiencies come first, tagged [Format], citing 01 33 00 or the project's format requirements.

**3. Coordination Items:** items still needing review by a consultant, delegated engineer or another trade. Table: Item | Discipline | Reason (with citation).

**4. Open Ends:** questions for the architect or contractor; disagreements between consultant and architect comments; consultant comments that conflict with the contract documents or may change scope; consultant comments not yet received; whether the default format checklist was used in place of project requirements; and documents that were missing or may have a newer version, which limited the review.

Keep the whole response concise. No preamble, no recap of the process.
