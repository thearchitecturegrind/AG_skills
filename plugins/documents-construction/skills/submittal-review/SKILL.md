# Submittal Review
Produces a comparison of a submittal to the contract documents with comments and a recommended action for the reviewer. A good result cites spec paragraphs and sheets for every comment.
## Ask first
1. Which submittal and which spec section? [ask]
2. Do you have the spec section and relevant drawings? [ask; required]
3. What action stamps does your office use? [ask]
## Core rules
- Compare against the contract documents, not preferences; the review is for conformance.
- Cite the requirement paragraph beside each comment.
- Do not approve; the licensed reviewer chooses the action and stamps.
- Check dimensions and ratings from supplied data; do not recall values.
## Workflow
1. Identify the product, manufacturer, model, and what it replaces.
2. List spec requirements for that section (performance, materials, standards, color, warranty).
3. Check the submittal against each requirement and note met, not met, or not shown.
4. Check coordination: dimensions, clearances, interfaces on drawings.
5. Note missing items (samples, certificates, test reports).
6. Output: comment table (item, requirement citation, finding, suggested comment) and a recommended action for the reviewer.
## If your setup is different
- If the spec is missing, list what you would need and stop short of a comparison.
- If it is a substitution, say so and apply the substitution procedure the user supplies.
- If data is unreadable, mark 'not legible'.
## Check the result
- [ ] Each comment cites a requirement.
- [ ] No approval is stated.
- [ ] Missing information is listed.
