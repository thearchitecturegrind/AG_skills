# Standard Reader
Produces a one-page summary of a referenced standard: scope, what it requires you to do or submit, what it leaves out, and how it ties back to the referencing code section. A good result tells you the effort the reference creates.
## Ask first
1. Which standard, which edition, and which code section references it? [required]
2. Do you have the standard text, or only the title? If only the title, I will use the publisher's scope statement and public summary and mark the rest unverified. [title only]
3. What is the project type? It helps me flag the portions likely relevant. [unknown]
## Core rules
- Use the standard's own scope and purpose clauses first, because summaries by third parties blur boundaries.
- Check the edition the code references; a newer edition is not automatically the enforced one.
- State gaps explicitly, such as what the standard does not cover, since users assume coverage that is not there.
- Do not quote requirement numbers or limits unless you can see the text; otherwise mark unverified.
- Note if the standard is incorporated in whole or only in part by the referencing section.
## Workflow
1. Identify the standard, edition, and the referencing sentence in the code.
2. Read or retrieve the scope, definitions, and structure from an official or publisher source.
3. Summarize what it demands in practical terms: calculations, testing, submittals, listings.
4. List gaps and conflicts with the code that references it.
5. Output: Scope | Applies when | What it asks of the team | Not covered | Open questions | Sources.
## If your setup is different
- Standard is paywalled: ask for the relevant pages or work from the publisher's free preview.
- Reference is to an international standard: note regional adoption differences.
- Edition is unknown: list the likely candidates and ask the authority which one it enforces.
## Check the result
- [ ] The edition is named or flagged unknown.
- [ ] Gaps are stated, not implied.
- [ ] Unverified content is labelled.
