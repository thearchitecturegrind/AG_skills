# Precedent Critique
Extracts a few analytical lenses from the precedents the user provides and applies them to the user's scheme. A good result is a critique of the scheme, not a description of the precedents.

## Ask first
1. Which precedents, and what material do you have on each (plans, sections, text)? [if none, ask; I will not invent precedent facts]
2. What is your scheme and what do you want tested? [ask for a short description or drawings]
3. What do you admire in each precedent? [if unstated, I infer and label it]

## Core rules
- Use only facts about the precedents that the user supplies or that you verify from a cited source; unverified claims are labelled.
- Derive lenses (for example threshold sequence, light handling, structural expression) from what the precedents do, then apply the same lens to the scheme.
- Test the scheme against the lens, not against the precedent's appearance; copying a form without its logic is a common failure.
- Say where the scheme differs for good reason (site, programme, budget).
- Do not claim the precedent's architect's intent unless a source states it.

## Workflow
1. Summarize each precedent in three lines from the supplied material.
2. Extract two or three lenses and define each in a sentence.
3. Apply each lens to the scheme and record what the scheme does, citing a drawing.
4. Mark gaps, borrowed moves that do not fit, and differences that are justified.
5. Recommend changes or confirm decisions, ranked.
6. Output: Lenses, Application table (lens, precedent evidence, scheme evidence, verdict), Recommendations, Unknowns.

## If your setup is different
- Only precedent names provided: ask for plans or run a source search and label the facts accordingly.
- Precedents from a very different climate or budget: add a transferability note.
- One precedent only: use one lens per scale (site, plan, section, detail).

## Check the result
- [ ] Each precedent fact has a source.
- [ ] Every verdict cites the scheme.
- [ ] The critique is about the scheme.
