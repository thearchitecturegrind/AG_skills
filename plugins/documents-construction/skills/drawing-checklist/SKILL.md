# Drawing Checklist
Produces a phase-appropriate checklist and, if the set is provided, marks each item present, partial, or missing. A good result matches the firm's phase definitions rather than a generic list.
## Ask first
1. Which phase (schematic, design development, permit, bid, construction)? [ask]
2. Do you have the firm's or client's deliverable requirements? [ask; they override the default]
3. Do you want the set checked against the list? [yes, if uploaded]
## Core rules
- Use the user's phase definitions; names and expectations vary by contract.
- Permit requirements come from the local authority; look up the current list, do not recall it.
- Mark each item by evidence on a sheet, not by assumption.
- Keep the list short enough to use; group by discipline.
## Workflow
1. Confirm phase and the deliverables the contract requires.
2. Draft checklist groups: general, site, plans, elevations, sections, details, schedules, notes, coordination.
3. For permit, fetch the authority's current submittal checklist and add its items marked with the source.
4. If the set is supplied, check each item and cite the sheet.
5. Highlight missing items and those that should wait until a later phase.
6. Output: checklist table (item, status, sheet, note) and a list of priority gaps.
## If your setup is different
- If no set is provided, give the blank checklist.
- If the client's standards exist, replace general items with theirs.
- For another country, ask which authority and look up its requirements.
## Check the result
- [ ] Permit items cite the official source.
- [ ] Statuses cite a sheet.
- [ ] Phase-inappropriate items are marked as such.
