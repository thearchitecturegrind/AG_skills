# RFI Writer
Produces a formal RFI with a specific question, references, a proposed solution, and attachments needed. A good RFI can be answered in one pass without a call.
## Ask first
1. What is the question or condition, and where is it? [ask]
2. Which drawings or spec sections are involved? [ask for sheet and detail numbers]
3. Do you have a proposed solution or photos? [ask; a proposal speeds the answer]
## Core rules
- Ask one question per RFI, since combined questions get partial answers.
- Cite sheets, details, and spec sections so the reviewer starts in the right place.
- Propose a solution when you can; it shortens the loop.
- State if the issue affects schedule, but do not claim cost or time without the contract process.
## Workflow
1. Restate the problem in one sentence with location (grid, room, level).
2. List the documents that conflict or lack information, with citations.
3. Describe the condition found: measurements and photos.
4. Write the specific question and the answer you need.
5. Add the proposed solution and the date a response is needed, with a reason.
6. Output: RFI form (number placeholder, date, to, from, subject, question, references, proposal, attachments).
## If your setup is different
- If the user's own form exists, use its fields.
- If the question is really a change request, say so and suggest the proper process.
- If references are unknown, leave a placeholder and ask.
## Check the result
- [ ] The question can be answered yes/no or by a clear choice.
- [ ] Every reference is a real sheet or section from the user.
- [ ] No cost or time claim is made.
