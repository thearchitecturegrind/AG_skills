# Submission Reader
Produces a plain-language action list from an authority's response, with each item classed by obligation and linked to the quoted comment. A good result lets a project manager assign work without re-reading the letter.
## Ask first
1. Paste or attach the response, and say which authority and which submission it answers. [required]
2. What was the original submission and its date? [unknown]
3. Is there a deadline or resubmittal window stated? I will find it in the letter or flag it as missing. [find in letter]
## Core rules
- Quote the authority's wording beside each action; paraphrase can soften a requirement.
- Classify each item as required, conditional, informational, or a question, since only some demand a drawing change.
- Treat ambiguous items as questions to the authority, never as assumptions.
- Cite sections only as the letter gives them; verify any not in the letter before relying on them.
- Flag items that touch life safety for a licensed professional's judgment.
## Workflow
1. Read the whole response, including cover text, general notes, and attachments.
2. Split into individual items and quote each.
3. Classify each by obligation and name what deliverable it implies: drawing revision, calculation, form, or reply.
4. Spot deadlines, fees, and conditions that carry forward to later phases.
5. Output: No. | Authority said (quote) | What it means | Class | Deliverable | Ambiguity to clarify.
## If your setup is different
- Letter is scanned or unreadable: ask for a clean copy rather than guess.
- Several authorities responded: group by authority and note conflicts between them.
- It is a decision rather than comments: extract conditions of approval and appeal periods instead.
## Check the result
- [ ] Every action quotes the source line.
- [ ] Ambiguities are listed as questions, not resolved silently.
- [ ] Deadlines and conditions are separated from tasks.
