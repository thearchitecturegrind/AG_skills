# Punch List
Produces and updates a punch list where every item can be found, assigned, and closed. A good result lets a trade fix an item without a phone call.
## Ask first
1. Do you have notes, photos, or an existing list? [ask]
2. What room or area naming do you use? [use the drawings' room names and numbers]
3. Who are the trades or contractors? [ask]
## Core rules
- Each item needs a precise location; 'bathroom' alone sends people searching.
- Write the defect and the expected condition by reference to the spec or drawing, with a citation when you have one.
- Do not close an item without verification and a date.
- Safety or code concerns go to the licensed professional immediately, not onto a routine list.
## Workflow
1. Collect notes and photos; confirm room names against the plans.
2. Create one row per item: number, location, description, trade, reference, photo.
3. Group by room or trade as the user prefers.
4. Assign owner and target date; set status to open.
5. Update on rechecks: fixed, verified, rejected, with date.
6. Output: list table, counts by status and trade, and a reinspection list.
## If your setup is different
- If photos have no location, ask or mark 'location unknown'.
- If the contract defines punch procedure, follow the user's text.
- If items are disputed as out of scope, tag 'scope question' and link to the documents.
## Check the result
- [ ] Every item has location, trade, and status.
- [ ] Spec or drawing references are cited or marked none.
- [ ] Verified items show a date.
