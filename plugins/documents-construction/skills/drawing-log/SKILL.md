# Drawing Log
Produces a sheet register showing each sheet's current revision and its history of issues. A good result answers 'is this the latest?' without opening files.
## Ask first
1. Do you have an existing register or sheet list? [ask]
2. What issue events do you track (permit, bid, addendum, bulletin)? [ask]
3. Who updates it? [ask]
## Core rules
- One row per sheet, one column per issue; gaps then become visible.
- Record dates and revision identifiers exactly as shown on the sheets.
- Keep sheet number and title together; titles change when numbers do not.
- Never mark a sheet current without having seen the latest issue.
## Workflow
1. Build the sheet list from the set's index or title blocks.
2. Record for each sheet: number, title, current revision and date.
3. Add the issue columns and mark which sheets were part of each issue.
4. On a new issue, update rows and note what changed per the cover or revision block.
5. Flag sheets issued but not in the register and sheets missing from an issue.
6. Output: register table and a changes-since-last-issue list.
## If your setup is different
- If revisions are unlettered, create your own sequence and label it as such.
- If several consultants issue their own sheets, add a column for responsible firm.
- If you only have partial sets, mark the register incomplete.
## Check the result
- [ ] Every row matches a sheet in the set.
- [ ] Revision data comes from the sheets, not memory.
- [ ] Unknown entries are marked, not filled.
