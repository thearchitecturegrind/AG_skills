# Coordination Log
Produces a coordination log in which each conflict stays open until both documents are revised and checked. A good result prevents one fixed sheet from hiding a second contradicting sheet.
## Ask first
1. What conflicts do you have so far? [ask for list or documents]
2. Which disciplines are involved? [ask]
3. How will resolution be communicated (RFI, revision, bulletin)? [ask]
## Core rules
- List every document location involved in a conflict; fixing one is not closing it.
- Close an item only after each location is checked in the revised documents.
- Record the decision and who made it, with date and source.
- Keep wording neutral: 'A shows X; B shows Y'.
## Workflow
1. Create a row per conflict: ID, description, documents and locations, disciplines.
2. Record the proposed resolution, decider, and due date.
3. After revisions, verify each location and record the sheet and revision.
4. Mark status: open, decided, revised, verified.
5. Flag stale items and those affecting cost or schedule for the responsible party.
6. Output: log table and a short list of items awaiting a decision.
## If your setup is different
- If a model clash report supplies items, import rows and record its source.
- If the conflict affects cost, link to the change tracker, not this log alone.
- If you cannot access a revised sheet, mark 'unverified'.
## Check the result
- [ ] Each row names all affected locations.
- [ ] Verified items cite the revised sheet.
- [ ] Decisions show who and when.
