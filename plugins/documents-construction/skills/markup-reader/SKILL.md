# Markup Reader
Produces a numbered list of requested changes extracted from markups, with sheet location and who must act. A good result leaves nothing ambiguous, and flags illegible or conflicting marks.
## Ask first
1. Who made the markups, and for what purpose (owner review, consultant, field)? [ask]
2. Should the list be grouped by sheet, discipline, or person? [by sheet]
3. Is a clean set available to compare to? If yes, ask for it.
## Core rules
- Record each mark with sheet and location; an action without a place cannot be done.
- Quote the markup text exactly; paraphrase only in a separate column.
- Mark unclear items 'needs clarification' instead of guessing intent.
- Identify conflicts between markups; one reviewer may undo another.
## Workflow
1. List pages with markups and note the markup tool or colors used and what each color means, if stated.
2. Read each mark in order top to bottom, left to right.
3. Classify: change, question, approval, note to self, or unclear.
4. Write the action as an instruction: object, change, location.
5. Flag conflicts and items that affect other sheets or disciplines.
6. Output: numbered table (no., sheet, location, quoted markup, action, owner, status).
## If your setup is different
- If handwriting is hard to read, give your best reading with a confidence note.
- If markups sit in annotation layers, extract the text where tools allow, and still check visually.
- If there is no clean set, record locations as grid or room references.
## Check the result
- [ ] Every action has a sheet and location.
- [ ] Quotes match the markup exactly.
- [ ] Conflicts and unclear marks are listed, not resolved silently.
