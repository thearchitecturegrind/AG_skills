# Entitlement Tracker
Produces a single tracker with stages, dates, contacts by role, submittals, conditions of approval, and the deliverable that clears each condition. A good result lets anyone see the next action and the next deadline.
## Ask first
1. What approval is being sought, and with which body? [required]
2. Process steps and timelines from the jurisdiction's own procedure, or I will find them on its official site. [find]
3. Any dates already known, such as filing, hearing, or approval? [none]
## Core rules
- Dates drive risk, so every row has a date and a source (letter, notice, portal).
- Never invent timelines; copy them from the procedure document or mark them unknown.
- Treat conditions of approval as separate rows with an owner and the evidence that satisfies them.
- Note appeal or expiry periods, since missing them can void the approval.
- Keep contact names as roles unless the user supplies names.
## Workflow
1. Set up stages: pre-application, filing, completeness, review, hearing, decision, appeal period, conditions, expiry.
2. Record each stage's planned and actual dates and the source.
3. List submittals with status.
4. Enter conditions of approval with owner, due phase, and clearing document.
5. Output: Stage table, Conditions table, and a 'next three actions' list.
## If your setup is different
- Multiple approvals: use one tab per approval and a summary of dependencies.
- Approval has already been granted: start at the decision and track conditions only.
- Another country: relabel stages to local terms.
## Check the result
- [ ] Every date has a source.
- [ ] Conditions have clearing evidence.
- [ ] Expiry and appeal windows are stated.
