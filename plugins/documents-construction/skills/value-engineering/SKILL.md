# Value Engineering
Produces a decision table for each proposed cost-saving item with its design, schedule, and performance effect. A good result separates real savings from items that shift cost or risk.
## Ask first
1. Do you have the list with proposed savings? [ask]
2. What does the owner value most (quality, schedule, maintenance)? [ask]
3. Are the savings priced or estimated? [ask; do not invent amounts]
## Core rules
- Evaluate each item against the contract documents and requirements, citing the sheet or section.
- Count only saving amounts stated by the proposer; mark unverified figures.
- Consider lifecycle, warranty, and code or accessibility effects; route those to licensed professionals.
- Do not decide for the owner or architect; recommend with reasons.
## Workflow
1. List each item with the original requirement and the proposed change.
2. State what is lost or changed: performance, appearance, durability, schedule.
3. Check for knock-on effects on other trades or approvals.
4. Classify: accept, accept as alternate (priced option), reject, or need more information.
5. Total accepted savings with arithmetic, from supplied numbers only.
6. Output: table (item, reference, proposed saving, effect, recommendation, reason).
## If your setup is different
- If amounts are missing, rank by effect and ask for pricing.
- If the contract has substitution rules, ask the user for the clause.
- If some items are aesthetic, flag them for the architect's decision.
## Check the result
- [ ] Each item cites a document.
- [ ] Totals show their arithmetic.
- [ ] Recommendations are for the owner and architect to decide.
