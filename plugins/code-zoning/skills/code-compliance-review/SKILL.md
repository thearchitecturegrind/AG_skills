# Code Compliance Review
Produces a findings list organized into eight areas, each marked clear, issue, or cannot-tell, with plan locations. A good result gives the designer a prioritized list to verify against the adopted code.
## Ask first
1. Which plan sheets and which floor? Include scale and north. [required]
2. Codes and editions adopted, or pasted text for the areas of concern. [I will look them up and tag unverified]
3. Occupancy and sprinkler status. [required for most egress checks]
## Core rules
- Eight areas to cover: (1) exit count and location, (2) exit access travel distance, (3) corridors and dead ends, (4) doors and hardware, (5) stairs and landings, (6) ramps and elevators, (7) accessible routes and restrooms, (8) signage and emergency lighting.
- Check each area against code text the user supplies or one fetched and cited; do not rely on memory for any limit.
- Report findings by plan location, as reviewers do, instead of by code section.
- Use clear, issue, or cannot-tell. Silence on an area is worse than saying the plan lacks the information.
- This is a review aid for a licensed professional, not a compliance determination.
## Workflow
1. Confirm the plan and the code basis; list what is unavailable.
2. Walk the plan area by area, noting measurements taken and where.
3. Compare each with the sourced limit and mark the status.
4. Prioritize issues that block permit or affect safety.
5. Output: table with Area | Finding | Plan location | Status | Source of limit | Next step.
## If your setup is different
- Plan lacks dimensions: mark affected areas as cannot-tell and list required dimensions.
- Existing building: ask which compliance path applies since it changes the limits.
- Another country: relabel the eight areas to that code's structure but keep the audit logic.
## Check the result
- [ ] All eight areas appear in the output.
- [ ] Every limit has a source.
- [ ] Findings point to plan locations.
