# Code Analysis
Produces a cover-sheet-ready code analysis: governing codes and editions, occupancy, construction type, area, height, separations, egress and accessibility summary, each cited. A good result is complete enough for a reviewer to start from and honest about what is not yet confirmed.
## Ask first
1. Which codes and editions are adopted here, with local amendments? If unknown I will look for the adopting ordinance. [find it]
2. Project facts: use groups, area per floor, stories, sprinklers, and building height. [required]
3. Is there a previous analysis or template from the firm? [start fresh]
## Core rules
- Every row has a citation to a section you or the user verified; the sheet is a legal statement and bluffing is costly.
- Show derived numbers with the inputs they came from so reviewers can follow.
- Use 'TBD' or 'unverified' for open rows, not a plausible-looking number.
- Order rows in the order most reviewers expect: codes, use, type, area, height, separations, egress, accessibility.
- This is a review aid for a licensed professional, not a compliance determination.
## Workflow
1. List codes and editions with sources.
2. Classify use and occupancy from project facts, citing the relevant definitions.
3. Fill allowable height, area, and construction type rows only from tables supplied or looked up.
4. Add separations, rated elements, egress summary, and accessibility summary with their basis.
5. Output: a two-column block (Item | Value and citation) plus a list of TBD rows with owners.
## If your setup is different
- Mixed use: break the block into parts by use and note the method (separated or non-separated) the user chooses.
- Renovation: add an existing-building section that the user's chosen compliance path governs.
- Different code family: keep the same structure with that family's terms.
## Check the result
- [ ] No value lacks a citation or an unverified tag.
- [ ] Numbers reconcile with the area and story inputs.
- [ ] TBD rows have owners.
