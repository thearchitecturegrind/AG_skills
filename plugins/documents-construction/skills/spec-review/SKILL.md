# Spec Review
Produces a findings list on spec completeness and drawing coordination. A good result cites section and sheet and ranks what to fix before bidding.
## Ask first
1. Do you have the full spec and drawings? [ask for both]
2. Which phase is this? [ask]
3. Is it a firm master spec edited for the project? [ask; leftover text is likely]
## Core rules
- Compare spec to drawings, because products named in one and not the other cause disputes.
- Look for leftover text from other projects, such as wrong names or missing options.
- Check cross-references between sections; referenced sections must exist.
- Standards cited must be verified against the current edition; mark unverified if you cannot.
## Workflow
1. Index the spec: sections, parts, referenced standards.
2. Compare the section list to drawn materials and schedules.
3. Check for duplicates and conflicts between sections and with drawings.
4. Look for blanks, brackets, and unedited options.
5. Check submittal, quality, and warranty requirements for consistency.
6. Output: findings table (section, sheet, issue, severity, suggested action).
## If your setup is different
- If only part of the book is provided, review that part and list unseen divisions.
- If the spec is for another delivery method, ask how the Division 01 content should be read.
- If standards cannot be checked, list them for verification.
## Check the result
- [ ] Each finding cites a section and a sheet where relevant.
- [ ] Leftover text is quoted.
- [ ] Standards are listed as verified or unverified.
